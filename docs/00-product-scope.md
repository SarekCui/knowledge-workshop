# 产品范围与业务边界

## 1. 产品定位

知识工坊是一个面向学习者、内容创作者和运营人员的线上知识服务平台。首要目标不是覆盖所有在线教育功能，而是形成一条可以真实演示和验证的业务闭环：

> 用户浏览付费课程 → 参加拼团 → 创建订单 → 完成模拟支付 → 拼团成团 → 获得课程权益。

当前已扩展课程/章节、Note、视频学习进度、签到积分与排行榜；技术社区和扩展运营后台仍在后续轮次。

## 2. 目标用户

| 用户 | 核心诉求 | 首版是否覆盖 |
|---|---|---|
| 学习者 | 低成本购买课程、查看权益、学习课程 | 已覆盖购买、权益、断点进度与 Note |
| 内容创作者 | 发布和维护课程 | 已覆盖管理员课程/章节最小接口 |
| 运营人员 | 配置课程、拼团活动并查看效果 | 首版提供最小管理接口 |
| 平台管理员 | 用户、内容、风控和系统治理 | 后置 |

## 3. 业务边界

### 首个业务闭环包含

- 课程商品的最小只读信息。
- 拼团活动创建、开启、参与、成团和过期。
- 订单创建、支付结果处理、取消和超时关闭。
- 成团后发放课程权益。
- 关键操作的幂等、补偿、审计和指标。

### 首个业务闭环不包含

- 对接真实支付渠道；只提供可替换的模拟支付适配器。
- 视频转码、DRM、直播和大文件存储。
- 推荐算法、搜索集群和复杂内容审核。
- 多币种、退款清算、发票和税务能力。
- 多租户与跨地域容灾。

## 4. 非功能目标

初始容量目标用于约束设计和压测，不代表生产承诺：

- 核心写接口在单实例本地压测下达到 100 RPS。
- 无外部故障时，核心接口 P95 小于 300 ms。
- 重复支付通知、重复消息和客户端重试不产生重复权益。
- 任一服务重启后可通过数据库与消息恢复未完成业务。
- 单个下游不可用时具备超时、有限重试和可观测的失败状态。

容量目标必须在对应轮次通过固定环境压测后才能写成项目结果。

## 5. 事实与表达约束

- “已实现”表示代码、测试、运行文档和验收证据齐全。
- “已压测”必须记录机器配置、数据规模、脚本、持续时间和统计口径。
- “高可用”“零超卖”“最终一致”必须有明确故障模型和验证用例。
- 规划能力统一使用“计划”“拟采用”，不得写成已经交付。
