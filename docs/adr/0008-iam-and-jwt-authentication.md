# ADR-0008：IAM 服务与 JWT 认证边界

- 状态：已接受
- 日期：2026-09-08
- 决策人：项目维护者

## 背景

外部 API 已统一经过网关，但目前任何调用方都可以直接访问营销与积分接口。项目需要集中管理用户身份，并在网关入口建立统一认证，同时保留业务服务对资源所有权和业务权限的最终判断。

## 决策

- 新增 `knowledge-iam` 服务，独占 `knowledge_iam` schema，管理用户凭证、角色和登录。
- 密码仅保存 BCrypt 哈希；登录失败统一返回 401，不暴露账号是否存在、被禁用或密码错误。
- IAM 使用 HS256 签发短期访问令牌，包含 `sub`、`username`、`roles`、`iss`、`iat`、`exp` 和 `jti`。
- JWT 密钥只能通过 `JWT_SECRET` 环境变量注入，长度至少 32 字节，不在仓库提交可用密钥。
- 网关使用 Spring Security Resource Server 校验签名、签发方和有效期；登录接口与健康检查匿名可访问，其他 `/api/**` 默认要求认证。
- 网关只做通用身份认证和粗粒度访问控制；笔记所有权、课程权益等资源级权限仍由对应业务服务校验。
- Servlet 业务服务显式引入项目内部模块 `knowledge-security` 的资源服务器配置并独立验签，不信任客户端或网关传入的明文用户 Header；写操作以 JWT `sub` 作为用户身份事实。
- 认证失败使用统一 `Result<Void>`，保持真实 HTTP 401/403，并沿用网关生成的请求 ID。

## 刷新令牌后续决策（第 4.4 轮）

- 登录同时签发 30 分钟 JWT 访问令牌和 30 天不透明刷新令牌。
- 刷新令牌使用 256 bit 安全随机数，客户端只获得原文一次，IAM 数据库仅保存 SHA-256 摘要。
- 每次刷新都轮换令牌并记录替代关系；已轮换令牌再次出现视为泄露，撤销同一 `family_id` 下的整条会话。
- 注销接口撤销刷新令牌族并保持幂等。已签发的 JWT 不做逐请求 IAM 回查，最长在 30 分钟 TTL 后失效。

## 当前明确不包含

- JWT 访问令牌即时黑名单与设备级会话管理。
- 第三方登录、短信验证码、MFA 和密码找回。
- 租户、数据权限和完整后台 RBAC 管理界面。

这些能力必须在后续切片中独立设计、实现和验收，不能仅凭访问令牌实现宣称完成。

## 影响

- IAM 成为外部受保护接口的身份事实源；其数据库禁止被其他服务直接访问。
- JWT 验证无需网关逐请求同步调用 IAM，但密钥轮换需要双密钥过渡或升级为非对称签名。
- HS256 适合当前单环境作品化阶段；服务数量和密钥分发范围扩大时优先迁移到 RS256/ES256 与 JWKS。

## 验证方式

- 正确账号密码返回短期 JWT，错误密码和禁用账号均返回统一 401。
- 登录和刷新返回令牌对，原始刷新令牌不落库；每次刷新返回新的刷新令牌。
- 重用旧刷新令牌后，同族的新令牌也无法继续刷新；重复注销返回成功。
- 未携带、已过期或签名错误的令牌访问受保护 API 时，网关返回统一 401。
- 合法 JWT 可以通过网关进入受保护路由，角色声明可供后续授权使用。
