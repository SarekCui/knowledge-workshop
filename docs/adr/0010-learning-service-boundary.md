# ADR-0010：课程与学习能力首版合并边界

- 状态：已接受
- 日期：2026-09-08
- 决策人：项目维护者

## 背景

目标架构曾将课程内容与学习权益拆为两个服务，但当前需要同时实现课程、章节、Note、视频进度和权益闭环。若此时拆成 course 与 learning 两个服务，Note 和进度在每次写入时都需要同步查询课程与视频版本，增加尚无独立团队和发布节奏支撑的远程依赖。

## 决策

- 新建 `knowledge-learning` 服务，由它拥有课程、章节、Note、课程权益和视频进度数据。
- 服务内部按 `course`、`note`、`progress`、`entitlement` 业务域分包，各域内使用传统分层架构。
- 营销服务不访问学习数据库，通过 `GroupFormed` 事件异步发放权益。
- 当课程内容具备独立团队、容量或发布节奏后，再通过新 ADR 评估拆分 course 服务。

## 备选方案

- 立即拆分 course 与 learning：边界理论上更细，但当前会引入高频同步调用与双服务联调，收益不足。
- 把学习能力放入营销服务：会混淆营销交易与学习事实的数据所有权，不采用。

## 影响

### 正面影响

- 课程版本、Note 关联、进度校验和权益校验均可在本服务完成。
- 保持微服务数量与真实业务边界匹配。

### 代价与风险

- 课程内容与学习数据暂时共同发布。
- 未来拆分时需要建立课程快照或内部查询契约。

## 验证方式

- 学习服务可独立迁移数据库并启动。
- 营销成团事件重复投递时权益只发放一次。
- 课程、Note、进度和权益均不能被其他服务直接访问数据库。
