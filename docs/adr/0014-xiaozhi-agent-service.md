# ADR-0014：小智 Agent 独立服务与首期交互边界

- 状态：提议
- 日期：2026-09-17
- 决策人：项目维护者（待确认）

## 背景

项目计划增加两个 AI 入口：全局右侧“问小智”，以及公开 Note 评论区通过 `@小智` 请求回答。该能力需要管理模型调用、流式输出、检索增强、工具权限、会话记忆、异步任务、内容安全、成本与审计。把这些职责直接加入 `knowledge-learning` 会使课程学习服务同时承担模型供应商适配和 Agent 运行生命周期，也不利于后续独立限流、扩容和故障隔离。

同时，Agent 需要读取课程、Note、学习进度等现有业务数据，但不应成为这些数据的新事实源，更不能绕过服务边界直接读取其他服务数据库。

## 决策

- 提议新增 Java 17 + Spring Boot 服务 `knowledge-agent`，基础包使用 `com.knowledge.agent`。
- 使用 LangChain4j 作为首选 Agent 编排框架；业务层通过项目自定义的 `AgentModelService` 端口隔离框架类型。
- Agent 服务拥有独立 `agent_db`，保存会话、消息、运行、工具调用摘要、回答引用、Prompt/模型版本、Token 用量及消费幂等记录。
- 课程、Note、评论、进度、订单、积分、权益和用户资料继续归原服务所有；Agent 通过受鉴权内部 API 或事件访问，禁止跨服务访问数据库。
- 右侧问答使用经网关鉴权的 SSE 流式响应；客户端页面上下文只作为提示，资源可见性由服务端重新校验。
- 评论区 `@小智` 由 learning 在评论本地事务中写入 `AgentMentioned` Outbox，经 RabbitMQ 至少一次投递；Agent 幂等消费并通过 learning 内部接口幂等发布带 AI 标识的回复。
- 私人问答与公开评论使用不同工具白名单。公开评论只能访问公开资料，不得访问提问者私人 Note、进度、订单或积分。
- MySQL 中的完整消息和运行记录是事实源；LangChain4j Chat Memory 只用于模型上下文窗口。同一会话首期串行生成。
- 首期写工具仅考虑“经用户确认创建 Note 草稿”，不开放交易、权益、积分或发布内容等高风险写操作。
- 向量存储、Embedding 模型、切分与重排策略在原型验证后另行确认；本 ADR 不提前绑定具体实现。

## 备选方案

- 将 Agent 能力直接加入 `knowledge-learning`：初始模块更少，但会混合学习事实与模型编排、成本审计和异步运行职责，不采用。
- 使用 Python LangChain 新建服务：AI 生态丰富，但当前主要工作是 Java 微服务鉴权、事件、幂等与业务工具编排，会新增第二套工程治理体系；首期不采用，复杂模型处理出现明确需求后再评估独立 Worker。
- 使用 Spring AI：与 Spring 生态集成紧密，但项目希望将 LangChain 系列作为 Agent 技术亮点，因此首期选择 LangChain4j，同时保留业务端口避免框架锁定。
- 只在前端直接调用模型：会暴露模型密钥，无法可靠执行权限、审计、限流和异步评论，不采用。

## 影响

### 正面影响

- Agent 运行、模型供应商与业务事实边界清晰，可独立限流、扩容和降级。
- 同一套内核支持私人流式问答和公开异步回复，但工具权限可以按场景隔离。
- 运行、引用、成本和失败均可追溯，避免只形成不可审计的聊天 Demo。
- 保持原服务数据所有权和资源级权限模型。

### 代价与风险

- 新增服务、schema、内部契约、MQ 事件和部署单元，增加运维与测试成本。
- 模型输出不确定，必须建立评估集、引用校验、内容安全和失败降级。
- LangChain4j 同一 Memory ID 的并发使用需要额外串行控制。
- SSE 连接、模型超时和 Token 成本需要专门的容量与预算治理。
- RAG 数据同步可能存在延迟，检索结果仍需做可见性和来源版本校验。

## 验证方式

- 未授权用户不能读取他人的会话、私人 Note 或学习进度。
- 公开评论 Agent 的工具集合中不存在私人数据工具。
- 同一评论事件重复投递至少 10 次，只生成一条小智回复。
- learning 提交评论成功而 MQ 暂时不可用时，Outbox 可恢复发送。
- 同一会话并发提问只允许一个运行，另一个得到稳定冲突响应。
- SSE 正常、断开、模型超时和服务重启均产生可识别且可审计的运行状态。
- 回答引用可定位到当前用户有权访问的来源和版本。
- Prompt 注入测试不能扩大工具权限或绕过服务端鉴权。
- 固定评估集记录回答正确性、引用有效率、首 Token/P95、失败率和 Token 成本；达到后续确定的门槛后才能标记完成。
