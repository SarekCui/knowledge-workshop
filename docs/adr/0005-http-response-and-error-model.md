# ADR-0005：HTTP 成功包装与错误模型

- 状态：已替代（见 ADR-0006）
- 日期：2026-09-03

## 背景

项目原有 `ApiResponse<T>`，但成功和错误共用同一结构，且所有业务异常都返回 400。这样会削弱 HTTP 状态码语义，客户端、监控和网关难以区分资源不存在、状态冲突和系统失败；名称还会与 OpenAPI 的 `ApiResponse` 注解冲突。

## 决策

- 普通 JSON 成功响应显式使用 `ApiResult<T>`，为 React 客户端提供稳定的 `data`、`code` 和追踪元数据，并避免 OpenAPI 注解使用全限定类名。
- 错误响应改用 RFC 9457 `ProblemDetail`，通过扩展字段携带业务 `code`、`requestId`、`timestamp` 和字段错误。
- 业务异常必须显式选择 400、404 或 409 等状态分类；未知异常固定对外返回 500 通用描述，并在服务端记录带请求 ID 的堆栈。
- 不使用全局响应体切面自动包装；无正文、二进制和流式响应保留原生协议语义。

## 影响

- 前端根据 HTTP 状态决定大类处理，根据稳定 `code` 决定业务分支，不解析 `message`。
- 原错误响应结构发生变化；当前尚未发布正式前端客户端，因此在生成客户端前完成迁移。
- OpenAPI 与契约测试必须覆盖 Problem Details 及关键错误状态。
