# 质量与验收标准

## 1. 完成定义（Definition of Done）

一项功能只有同时满足以下条件才算完成：

- 需求范围、成功路径和至少一个失败路径已文档化。
- 核心规则位于领域/应用层，而不是散落在 Controller 或 Mapper 中。
- 单元测试覆盖核心不变量，外部依赖具有集成测试或契约测试。
- API、数据库迁移、配置示例和运行说明同步更新。
- 错误可被稳定识别，日志包含请求 ID 与业务主键。
- 幂等、并发、超时、重试与补偿策略已说明并验证。
- 不包含密钥、调试后门、未受控 TODO 或静默吞错。
- 对应轮次的验收场景通过，并保存可复现命令。

## 2. 自动化质量门禁

### 每次变更

- Maven 编译与单元测试通过。
- 格式、静态检查和架构依赖检查通过。
- 新增代码不引入高危依赖漏洞。

### 合并前

- 受影响服务的集成测试通过。
- API 兼容性与数据库迁移得到检查。
- 至少一位评审者确认业务不变量和失败路径。

### 轮次结束

- 全量构建通过。
- 核心用户链路端到端通过。
- Docker 本地环境可从干净状态启动。
- 文档和实际实现一致。

## 3. 测试分层

| 层级 | 验证内容 | 是否依赖外部环境 |
|---|---|---|
| 单元测试 | 核心实体、状态机、规则链、金额与时间边界 | 否 |
| 应用测试 | 用例编排、幂等、事务边界（使用端口替身） | 否 |
| 集成测试 | MySQL、Redis、RabbitMQ、序列化与迁移 | Testcontainers |
| 契约测试 | 服务提供者与消费者字段/错误码兼容 | 否或最小服务 |
| 端到端测试 | 网关到权益发放的完整链路 | Docker 环境 |
| 非功能测试 | 并发、容量、恢复、安全和可观测性 | 固定测试环境 |

## 4. 必测边界

- 时间：活动边界时刻、时区、过期、调度重复触发。
- 数量：0、1、刚好满额、超过上限、并发最后一名额。
- 金额：0 元、折扣边界、精度、快照不一致。
- 状态：每条合法迁移和所有关键非法迁移。
- 幂等：相同请求、不同请求 ID、重复 MQ、乱序 MQ、重复回调。
- 故障：数据库/MQ/Redis 超时、服务重启、事务回滚、死信重放。

## 5. 性能证据格式

压测报告至少记录：

- Git commit、JDK/依赖版本和启动参数。
- CPU、内存、操作系统、容器资源限制。
- 数据规模、索引、缓存预热方式。
- 并发模型、持续时间、请求分布和思考时间。
- 吞吐、P50/P95/P99、错误率和资源指标。
- 瓶颈判断、优化前后对比及未解决问题。

缺少上述信息的数字只能视为临时观察，不能作为简历成果。
