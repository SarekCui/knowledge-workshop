# 第 5.4 轮：课程进度与我的课程

## 范围与接口

- `GET /api/learning/my-courses?pageNo=1&pageSize=20`：仅查询本人有效权益且已发布的课程，以课程去重，分页最多100条。按最近进度更新时间排序，无进度时使用课程创建时间，课程ID作为稳定次级排序。
- `GET /api/learning/courses/{courseId}/progress`：本人课程进度，返回课程标题、封面、当前发布视频总数、完成数、整数百分比、续播章节/视频/版本/位置和进度更新时间。

用户身份统一来自 UserContext，不接受客户端 userId。课程不存在或未发布返回404，无有效权益返回403，未认证返回401。

## 数据口径

视频必须是当前最新版本且已发布；旧版本和下架章节不计入分母与完成数。完成判断沿用单视频 COMPLETED 状态，课程百分比为完成视频数除以总数乘100，向下取整，范围0—100；零视频课程为0。此百分比不同于单视频按有效观看时间计算的万分比。

最近视频使用当前版本数据库进度的 updated_at 排序，仅 last_event_id 非空的已处理学习进度可成为最近位置，不把只创建播放会话等同于实际学习。无学习记录返回按 sort_order / chapterId 排序的首个视频及0位置；无可学习视频返回空章节/视频/版本。lastLearnedAt 表示数据库进度更新时间，不宣称客户端实际观看时刻。

查询为学习服务同库只读投影，使用 CourseLearningMapper JOIN 自有课程、权益和进度表，不调用其他服务数据库或其他领域Mapper。Service开启只读事务，使分页总数和内容使用同一数据库快照。权益通过 EXISTS 判断，同一用户多个权益来源不重复列出课程。不新增Redis缓存、进度投影表或消息类型。

进度上报仍沿用已有幂等、乱序和多设备规则。聚合读取数据库，所以异步消息尚未消费时可能短暂滞后；Redis清空不影响已落库聚合。V3增加 user_id / course_id / updated_at 索引支撑最近位置查询。本批不包括下架、失效或尚未取得权益的“全部历史购买订单”，我的课程准确语义是“我的可学习课程”。

## 验收入口

- CourseCompletionRuleTest：空课程、百分比向下取整、全完成、非法计数。
- LearningAcceptanceIT：重复进度事件、多个权益来源去重、Redis清空、分页及空页、版本切换不沿用旧完成数、未学习首视频、无发布视频、未认证、他人访问、权益失效、课程下架与OpenAPI路径。
- 原 Note、权益发放、消息死信、视频进度乱序及多设备场景继续回归。
