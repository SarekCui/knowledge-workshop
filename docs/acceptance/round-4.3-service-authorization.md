## 完成内容

- 新增项目内部模块 `knowledge-security`，为 Servlet 业务服务统一提供 HS256 JWT 验签、签发方/有效期校验、角色映射和统一 401/403；由各业务服务显式导入配置，不采用 Starter 自动装配语义。
- 营销与积分服务独立验证原始 Bearer Token，不信任可伪造的明文用户 Header，因此绕过网关也不能免认证。
- 参团 DTO 删除 `userId`；Controller 将 JWT `sub` 与 DTO 显式转换为 `JoinGroupBO`，订单及参与记录以认证身份落库。
- 签到接口删除用户 ID 请求体，始终使用 JWT `sub`，防止替他人签到。
- 支付服务校验订单所有者，不匹配时返回 403。
- 安全链提前返回 401/403 时也会校验或生成请求 ID，并保证响应头与统一响应体一致。
- OpenAPI 契约同步删除客户端可指定的签到用户身份。

## 边界

- 本轮覆盖当前已有的参团、支付和签到写接口；第 5 轮新增笔记、课程权益等资源时仍需逐资源实现所有权规则。
- HS256 仍要求网关与业务服务共享验证密钥；服务规模扩大后按 ADR-0008 迁移到非对称签名与 JWKS，避免验证方持有签发能力。
- 排行榜目前要求登录但不限制只看本人，因为它是面向学习者公开的赛季榜单。

## 结论

现有用户写操作已经不再信任请求体用户 ID，网关和业务服务形成纵深认证，订单所有权由营销服务最终判定。第 4 轮下一切片进入刷新令牌或服务容错。
