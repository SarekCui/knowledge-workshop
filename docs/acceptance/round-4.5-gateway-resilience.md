# 第 4.5 轮验收记录：网关同步调用容错

- 验收日期：2026-09-08
- 环境：Java 17、Spring Cloud Gateway、Resilience4j、Reactor Netty 临时故障服务

## 实现范围

- Gateway 到 IAM、营销、积分的连接超时、响应超时和固定连接池上限。
- 每个下游独立的 CircuitBreaker、TimeLimiter 与 SemaphoreBulkhead。
- 仅 GET 最多重试 1 次；写请求禁止透明重试。
- 统一 HTTP 503 降级响应和请求 ID 透传。
- 直接访问内部降级端点返回 404。

## 验收结果

| 场景 | 结果 |
|---|---|
| Gateway 6 个单元测试 | 通过，0 失败、0 错误 |
| Gateway 3 个真实 HTTP 故障验收场景 | 通过，0 失败、0 错误 |
| GET 短暂 503 后仅重试一次并恢复 | 通过 |
| POST 遇到 503 不重试 | 通过 |
| 慢响应超过阈值后统一返回 503 | 通过 |
| 连续失败开路、开路期间不访问下游、半开探测后关闭 | 通过 |
| Bulkhead 超额请求立即拒绝 | 通过 |
| 降级响应保留 `X-Request-Id` 与统一 `Result<Void>` | 通过 |

## 备注

验收中的 200 ms、5 次失败等参数用于快速验证状态迁移；运行配置使用 1 秒连接超时、3 秒响应超时、5 次最小统计样本和 10 秒开路窗口。并发阈值需要在第 6 轮固定环境压测后再校准，当前不能作为生产容量承诺。

当前完成的是外部入口的真实同步链路治理。仓库还没有业务服务间同步 HTTP 调用；后续出现课程快照等真实用例时，再为调用方增加 OpenFeign/RestClient 契约和独立容错配置。
