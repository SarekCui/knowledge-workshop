# 第 5.2 轮：营销查询与运营后台验收记录

## 1. 交付范围

- 用户侧分页查询当前可参与的拼团活动、活动下有效团实例和团详情。
- 用户侧分页查询本人交易订单及订单详情，禁止越权读取他人订单。
- 管理员创建、修改、开启和关闭拼团活动，并为有效活动创建团实例。
- 管理员分页查询通知任务，将 `RETRY` 或 `DEAD` 任务重新排入可靠通知调度。
- 引入统一 `PageBO<T>` 与 `PageVO<T>`，MyBatis-Plus 分页请求最大为 100 条。

## 2. 分层与命名

Controller 只接收 DTO、返回 VO；Service 使用 BO；Mapper 只持久化 DO。交易订单统一命名为
`TradeOrderBO/VO`，团实例统一命名为 `GroupDetailBO/VO`，避免原 `GroupOrder` 同时表达团和交易订单。

## 3. 幂等与并发

- 创建活动和建团由调用方提供唯一资源 ID；相同 ID 与相同参数重复提交返回原资源。
- 相同 ID 携带不同参数返回 409，避免静默覆盖。
- 活动修改和状态迁移使用 `version` 乐观锁；并发变化返回 409。
- 人工重试通过条件更新，只允许 `RETRY/DEAD -> PENDING`；实际投递仍由可靠通知任务调度器执行。

## 4. 自动化验收

`MarketingAcceptanceIT` 覆盖：

- 用户查询活动与团、读取本人订单、越权读取返回 403。
- 学员访问运营接口返回 403。
- 管理员创建、修改、开启活动以及幂等建团。
- 失败通知任务人工重试后进入 `PENDING` 且清除上次错误。
- OpenAPI 文档包含新增用户与管理员路径。

执行：

```bash
mvn -Dmaven.repo.local=.m2/repository verify -Pacceptance
```
