# 技术 Note 标签设计

## 1. 范围与约束

- 每篇 Note 最多设置 5 个技术标签，单个标签 1—20 个字符。
- 服务端执行 Unicode NFKC 归一、首尾/连续空白整理与大小写无关去重；展示保留首次输入形式。
- 标签属于 Note 聚合的写入范围，创建和正文更新时与 Note 在同一本地事务内替换。
- 创建幂等指纹包含标签；相同 `idempotencyKey` 携带不同标签时返回冲突，不能回放旧结果。

## 2. 数据模型

`note_tag` 使用 `(note_id, normalized_name)` 作为主键，以 `(note_id, sort_order)` 保证展示顺序唯一，
并通过 `(normalized_name, note_id)` 支持精确标签检索。标签不建立独立全局实体，避免过早引入运营词库与标签生命周期。

读取列表时先分页查询 Note，再按本页 Note ID 批量查询标签，避免逐条读取形成 N+1 查询。

## 3. 检索语义

- `keyword`：继续匹配标题和正文，同时匹配规范化后的标签子串。
- `tag`：大小写无关的规范化后精确匹配，作为公开信息流的可组合筛选条件。
- 标签按钮只更新 `NoteBrowseStore`，分页、排序和筛选状态由 Context 暴露，不逐层传递业务状态与方法。

当前数据量采用关系表与 `EXISTS` 查询；后续只有在真实容量和查询延迟证明需要时，才引入搜索引擎或标签聚合缓存。

## 4. 安全与一致性

- DTO Bean Validation 与服务层防御性校验同时限制数量和长度。
- 标签拒绝空值和控制字符，SQL 参数均由 MyBatis 参数绑定，不拼接用户输入。
- Note 软删除后公开查询以 Note 状态为边界；标签通过外键保留，便于恢复或审计，不单独暴露。
